# Q31：`storage`、`memory` 与 `calldata` 的区别和使用场景

| 位置 | 持久化 | 可修改 | 适用场景 | Gas 成本 |
|------|--------|--------|---------|----------|
| `storage` | 链上永久存储 | 可修改 | 状态变量、跨函数持久化数据 | 读写成本高 |
| `memory` | 仅在调用期间存在 | 可修改 | 函数内部临时变量、函数参数 | 成本较低 |
| `calldata` | 仅调用期间存在 | 不可修改（只读） | 外部函数的引用类型参数 | 更低（只读） |

- `calldata` 与 `memory` 相似，但完全不可修改且 gas 更低。用于 `external` 函数的数组、结构体等复杂类型参数。
- 对于引用类型（数组、struct、映射），必须显式指定位置。函数参数默认 `memory`（内部函数）或 `calldata`（外部函数）。
- 避免在 `storage` 中读多次，可用 `memory` 缓存。
