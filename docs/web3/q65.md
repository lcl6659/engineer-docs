# Q65：EIP-7702 的核心原理：EOA 如何"临时变成"智能合约？

在 EIP-7702 之前，一个以太坊地址究竟是 EOA 还是合约地址，从它诞生起就固定了。EIP-7702 则引入了一种全新的交易类型 **Type 0x04**，赋予普通账户"临时借用"或设定代码的能力。

**技术实现细节：**
1.  **交易结构**：Type 4 交易的 RLP 编码结构为：
    `0x04 || rlp([chain_id, nonce, max_priority_fee_per_gas, max_fee_per_gas, gas_limit, destination, value, data, access_list, authorization_list, signature_y_parity, signature_r, signature_s])`
    其中 `authorization_list` 字段是 EIP-7702 的核心创新，格式为
    `authorization_list = [[chain_id, address, nonce, y_parity, r, s], ...]`
    每个授权元组包含：`chain_id`（指定授权生效的链）、`address`（授权委托的目标合约地址）、`nonce`（必须与授权账户当前的 nonce 值匹配），以及 `y_parity, r, s`（授权账户对该授权的签名数据）。
2.  **执行流程**：当用户的 EOA 发起一笔 Type 0x04 交易，并附上对特定智能合约的授权签名后，EVM将验证 `authorization_list` 中每个授权的签名有效性；如果授权包含代码实现，节点在执行这笔交易时会把这段代码**暂时挂载**到用户的 EOA 地址上；此时该地址就像一个智能合约账户，可以执行自定义验证逻辑、批量调用、Gas 代付等操作。
3.  **灵活的代码挂载方式**：在执行完成后，若是一次性授权（临时代码），执行结束即恢复为普通 EOA；若授权关系持久留存，该地址就表现为"长期有 code"。EIP-7702 还支持实现"最小代理"——通过简单的 `setCode` 交易来部署真正的轻量代理，可将部署和初始化实现在单笔原子交易中。
