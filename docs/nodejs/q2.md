# Q2：Node.js 的事件循环（Event Loop）是怎样工作的？

Node.js 的事件循环是其实现异步非阻塞的核心机制。它要处理 JavaScript 异步回调，分多个阶段轮询。

**六个阶段**（每轮称为一个 tick）：

1.  **timers**：执行 `setTimeout`、`setInterval` 到期的回调。
2.  **pending callbacks**：执行延迟到下一循环的 I/O 回调（如某些系统操作错误回调）。
3.  **idle, prepare**：内部使用。
4.  **poll**：轮询新的 I/O 事件，执行 I/O 相关回调（除 timers、close callbacks 和 setImmediate 之外的绝大部分回调都在此阶段）。如果 poll 阶段没有定时器到期，会在此等待。
5.  **check**：执行 `setImmediate` 的回调。
6.  **close callbacks**：执行 close 事件回调，如 `socket.on('close', ...)`。

**每个阶段之间会检查并清空微任务队列**（`process.nextTick` 和 Promise 回调），`process.nextTick` 优先级高于 Promise。
