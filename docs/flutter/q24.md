# Q24：Flutter 的“三个树”重建机制详解（增量更新）

当 `setState` 调用后：

1. 对应的 Element 标记为 dirty。
2. 在下一帧，框架遍历脏 Element，调用它们的 `build()` 生成新 Widget。
3. 新 Widget 与 Element 持有的旧 Widget 比较（`canUpdate` 判断：类型相同且 Key 相同）。
   - 如果可更新：Element 保留，更新引用，递归更新子 Element。
   - 否则：Element 被移除，创建新 Element 并插入树中。
4. 布局和绘制阶段，仅脏的 RenderObject 或受影响的节点被重新布局/绘制。

这种增量更新避免了整棵树重建，极大提升了 UI 更新效率。
