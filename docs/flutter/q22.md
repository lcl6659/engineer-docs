# Q22：Flutter 的 Build、Layout、Paint 阶段分别做了什么？有什么优化策略？

- **Build 阶段**：执行 Widget 的 `build` 方法，产出新的 Widget 树。若 Widget 类型和 Key 未变，框架会更新已有的 Element（Widget 的实例化对象），复用其子 Element，避免重建。

- **Layout 阶段**：Element 树中对应的 RenderObject 接收约束，计算自身大小和子节点位置。该阶段从根到叶传递约束，叶到根返回大小。标记为 dirty 的节点参与，干净的节点跳过。

- **Paint 阶段**：RenderObject 根据绘制指令（如画矩形、文本）在 Canvas 上生成 Layer。标记为 dirty 的节点重新绘制，其 Layer 会被重新合成。

**优化策略**：
- 减少 Build 范围：拆分组件，将状态下沉；使用 `const` 避免无意义重建。
- 减少 Layout 次数：避免在 `build` 中读 RenderObject 尺寸引发额外布局。
- 减少 Paint 范围：用 `RepaintBoundary` 包裹静态或独立动画部分。
- 利用 `AutomaticKeepAliveClientMixin` 等缓存不可见子项。
