# Q12：状态管理方案有哪些？你为什么选择其中之一？

常用方案：
- **`setState`**：最简单，适合局部 UI，不适合全局或跨组件共享。
- **`InheritedWidget` + `ChangeNotifier`**：Provider 的底层原理。
- **Provider**（官方推荐）：简洁，结合 `ChangeNotifier` 或 `Stream`，依赖注入。
- **Riverpod**：编译安全，去中心化，无 BuildContext 依赖。
- **Bloc/Cubit**：基于事件和状态的响应式模式，可预测，适用于大型复杂业务。
- **Redux**：集中式 store，适合跨项目统一。
- **GetX**：轻量，集路由、状态、依赖注入，功能全但争议大。

选择依据：项目复杂度、团队熟悉程度、测试需求。一般小项目中用 Provider，大项目用 Bloc 或 Riverpod。
