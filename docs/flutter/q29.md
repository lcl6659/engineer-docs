# Q29：一个中大型 Flutter 项目的架构如何设计？

推荐采用**分层架构 + 功能模块化**：

- **底层基础设施层**：网络（Dio）、本地存储、日志、常量等。
- **数据层**：Repository 模式，统一管理数据来源（API、本地数据库），对外提供 Model。
- **业务逻辑层**：Bloc/Cubit、Riverpod 提供者等，接收 UI 事件，处理业务规则，输出状态。
- **表现层（UI）**：页面（Page）、组件（Widget），遵循组件化，纯 UI 与状态分离。

**组织方式**：
- 按功能模块划分文件夹（`features/`），每个模块内部分 `data/`、`domain/`、`presentation/`。
- 公共部分放在 `core/` 或 `shared/`。
- 路由集中管理，使用命名路由或 GoRouter。

**测试**：单元测试（逻辑层）、Widget 测试（UI）、集成测试。依赖注入（如 `get_it`、Riverpod）便于替换测试依赖。

**状态管理**：推荐 Bloc 或 Riverpod，因其可预测、可测试、与 UI 解耦。
