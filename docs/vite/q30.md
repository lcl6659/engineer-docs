# Q30：Rollup 与 Webpack、Vite 的核心区别是什么？

| 维度 | Rollup | Webpack | Vite（生产构建用 Rollup） |
|------|--------|---------|--------------------------|
| **设计初衷** | 打包 JavaScript 库，关注输出结果的简洁性与 Tree Shaking | 打包大型 Web 应用，关注各种资源管理、代码分割、HMR | 现代 Web 应用开发，兼具 Rollup 的生产优化与原生 ESM 的开发体验 |
| **模块支持** | 原生 ESM，对其他模块（CJS）需插件转换 | 通用模块加载器，支持 ESM、CJS、AMD、图片、字体等一切资源 | 开发时利用浏览器原生 ESM；生产时用 Rollup 打包 |
| **Tree Shaking** | 天然支持且非常高效，因为 ESM 是默认一等公民 | 支持，但需要配置确保 ESM，并且副作用标记 | 继承 Rollup 的 Tree Shaking 能力 |
| **输出格式** | 直接输出多种格式（ESM、CJS、UMD 等） | 主要是自执行 bundle（或通过 module 字段输出 ESM） | 最终产物是标准静态资源，由 Rollup 决定 |
| **代码分割** | 支持动态导入分割，但配置相对原始 | 内置强大的 `splitChunks`，自动/手动提取公共代码 | Rollup 的 `output.manualChunks` |
| **静态资源处理** | 需插件（如 `rollup-plugin-image`） | 原生 Loader 机制处理任何文件 | Vite 里内置处理，最后交给 Rollup 插件 |
| **开发服务器/HMR** | 不直接提供，需搭配其他工具 | 内置 DevServer 和 HMR | Vite 自己的开发服务器，HMR 极快 |
| **使用场景** | 库、SDK、CLI 工具 | 大型 SPA、传统多页应用 | 现代 Web 应用（Vue/React）、静态站点 |

**总结一句话**：Rollup 是为库打包而生，Webpack 是为应用打包而生，Vite 用 Rollup 做生产打包同时提供了极致的开发体验。
