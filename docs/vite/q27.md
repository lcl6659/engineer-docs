# Q27：如何定位并解决 Vite 开发环境下的性能瓶颈？

Vite 开发时虽然很快，但随着模块数量增加，也可能出现瓶颈：
- **依赖预构建过慢**：运行 `npx vite optimize --force` 重新构建缓存，查看 `node_modules/.vite/deps` 目录下的依赖是否有不必要的庞大库。
- **大量的导入请求**：打开浏览器 DevTools 的 Network 面板，观察Pending 的请求瀑布。合并小模块或动态导入。
- **TypeScript 检查**：`vue-tsc` 或 `tsc --noEmit` 检查类型可能成为编译瓶颈。可拆分到独立进程，或使用 `fork-ts-checker-webpack-plugin` 的 Vite 等价方案。
- **过多的 HMR 边界**：未正确设置 `HMR`，导致整个页面刷新而非局部替换。
- **使用 Vite 的 `build.reportCompressedSize` 可以看到压缩后大小**，便于分析。

**调优方式**：
- 使用 `vite --debug` 查看详细日志。
- 配置 `server.warmup` 提前转换频繁访问的模块。
- 更新 Vite 版本以获取性能改进。
