# Q38：如何用 Rollup 打包一个现代化的 JavaScript 库？最佳实践有哪些？

**推荐配置模板**：
```javascript
// rollup.config.js
import resolve from '@rollup/plugin-node-resolve';
import commonjs from '@rollup/plugin-commonjs';
import babel from '@rollup/plugin-babel';
import { terser } from 'rollup-plugin-terser';

export default {
  input: 'src/index.js',
  output: [
    { file: 'dist/my-lib.cjs.js', format: 'cjs' },
    { file: 'dist/my-lib.esm.js', format: 'es' }
  ],
  external: ['react', 'lodash'],  // 所有生产依赖都外部化
  plugins: [
    resolve(),   // 解析 node_modules
    commonjs(),  // 转换 CommonJS
    babel({ babelHelpers: 'bundled', exclude: 'node_modules/**' }),
    terser()     // 生产构建时压缩（可选）
  ]
};
```

**最佳实践**：
1. **使用 `external` + `peerDependencies`**：在 `package.json` 中将核心依赖放入 `peerDependencies`，并外部化，避免重复打包。
2. **提供多种输出格式**：至少输出 ESM 和 CJS 两种格式，并在 `package.json` 中分别通过 `module`、`main` 字段指向对应文件。
3. **保留原始 ESM 结构**：如果希望消费者能够进一步 Tree Shake，应输出保留模块结构的 ESM（`preserveModules: true`），而不是打平所有代码到一个文件。
4. **开启 Tree Shaking**：利用 Rollup 默认能力，并在 `package.json` 中声明 `"sideEffects": false`。
5. **使用 Babel 或 TypeScript**：编译现代语法，保证浏览器兼容性。
6. **生成 Source Map**：便于调试。
7. **发布前检查**：`rollup-plugin-filesize` 显示文件大小，`rollup-plugin-visualizer` 分析包组成。
