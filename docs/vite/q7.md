# Q7：Webpack 的 HMR（热模块替换）原理是什么？

HMR 允许在应用运行时替换、添加、删除模块，而无需完全刷新页面，保留应用状态。

**流程**：
1. **Webpack Dev Server** 启动时，会与浏览器建立一个 **WebSocket** 连接。
2. **文件变化** → Webpack 重新编译变化模块，生成“热更新文件”（含 manifest 信息，列出更新模块和依赖）。
3. **推送更新**：Dev Server 通过 WebSocket 向浏览器发送更新通知。
4. **浏览器接收**：HMR runtime（注入的代码）收到消息后，请求 `hot-update.json`（manifest）和 `hot-update.js`（更新的模块代码）。
5. **模块替换**：客户端 runtime 执行新模块代码，找到旧模块并执行 `module.hot.accept` 回调（如果模块自行处理），或冒泡交给父模块处理。若全部无法处理，则回退到页面刷新（Live Reload）。

**关键点**：HMR 不刷新页面，状态保留依赖于开发者是否在模块中正确处理 `module.hot.accept`。React 的 React Hot Loader 或 Fast Refresh 正是在其基础上实现了组件状态的热替换。
