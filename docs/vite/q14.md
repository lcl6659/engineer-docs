# Q14：Vite 的 HMR 原理与 Webpack 有何不同？

- **Webpack**：每次改动，HMR 需要重新构建模块及其依赖图，然后通过 WebSocket 推送新版块，客户端替换模块。当项目规模增大，这个图的重计算会有延迟。
- **Vite**：
  1. 文件变化由 `chokidar` 监听。
  2. 发送 WebSocket 消息通知浏览器。
  3. 浏览器**只请求变化的模块**（HTTP 请求），而无需重建整个依赖图。因为所有模块本来就是按需请求的 ESM。
  4. Vite 服务器即时编译该模块，返回给浏览器，由 Vite 客户端运行时处理更新。

**结果**：Vite 的 HMR 速度几乎不随着应用大小增加而下降，因为它只处理变更文件本身，与模块总数无关。
