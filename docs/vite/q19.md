# Q19：Webpack 与 Vite 的全面对比

| 维度 | Webpack | Vite |
|------|---------|------|
| **开发服务器启动** | 需打包整个应用，项目大时慢 | 按需编译，极快冷启动，几乎瞬时 |
| **HMR** | 随模块数量增加效率下降 | 精准更新，速度与模块总数无关 |
| **生产构建** | 自建打包，生态庞大 | Rollup（更优的 Tree Shaking） |
| **配置复杂度** | 配置较多，需要理解各种 Loader/Plugin | 开箱即用，配置简练 |
| **浏览器兼容** | 很好，传统 bundle 模式 | 开发环境需现代浏览器，生产可降级 |
| **生态** | 极其庞大，插件丰富 | 快速增长，Rollup 插件可直接复用 |
| **底层语言** | JS（可借助 esbuild/swc 加速） | esbuild（Go）预构建，开发编译飞快 |
| **适用场景** | 复杂大型项目，微前端，模块联邦等高级功能 | 现代 Web 应用，SPA/SSR，追求开发体验 |

**选择建议**：
- 新项目优先尝试 Vite，除非有 Webpack 专属的强依赖（如 Module Federation 复杂场景）。
- 大型已有 Webpack 项目可逐步迁移或局部启用 Vite。
