# Q3：Loader 和 Plugin 的区别是什么？请各自举一个常用的例子

| 维度 | Loader | Plugin |
|------|--------|--------|
| **作用** | 转换文件内容。让 Webpack 能够加载和解析非 JS 文件 | 扩展 Webpack 功能。在构建生命周期中执行更复杂操作 |
| **运行机制** | 作用在单个文件层级，根据不同文件类型调用不同 Loader 链 | 基于事件钩子，可以访问整个编译过程（Compiler 和 Compilation） |
| **配置位置** | `module.rules` 中，用 `test` 匹配文件，用 `use` 指定 Loader | 在 `plugins` 数组中实例化 |
| **关注点** | 文件内容转换 | 打包优化、资源管理、环境变量注入等宏观任务 |

**常用 Loader**：
- `babel-loader`：将 ES6+ 代码转换为 ES5。
- `css-loader`：解析 CSS 中的 `@import` 和 `url()`。
- `style-loader`：将 CSS 注入 DOM（在页面中插入内联 `style` 元素）。
- `ts-loader`：编译 TypeScript。
- `file-loader` / `url-loader`：处理文件资源（图片、字体等）。

**常用 Plugin**：
- `HtmlWebpackPlugin`：自动生成 HTML 文件并引入打包后的 JS/CSS。
- `MiniCssExtractPlugin`：将 CSS 提取到独立文件，而不是嵌入 JS。
- `DefinePlugin`：在编译时注入全局常量（如 `process.env.NODE_ENV`）。
- `TerserPlugin`：压缩 JavaScript。
- `CopyWebpackPlugin`：复制静态文件到输出目录。
