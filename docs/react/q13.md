# Q13：`useReducer` 的应用场景和使用方法

适合管理包含多个子值的复杂状态逻辑，或下一状态依赖于前一状态的情况。

`const [state, dispatch] = useReducer(reducer, initialState);`

- `reducer` 是 `(state, action) => newState` 的纯函数。
- `dispatch` 派发 action 更新状态。

常与 `useContext` 结合实现轻量级全局状态管理，将状态更新逻辑集中到 reducer 中，使代码更结构化，特别适合表单、步骤流程等场景。

`useReducer` 是 React 提供的一个 Hook，用于管理**复杂**或**多步**的状态逻辑。它是 `useState` 的进阶替代方案，尤其适合以下场景：

- 状态值有多个子属性（如对象、数组），且更新依赖当前状态。
- 下一个状态需要根据前一个状态计算得出（例如撤销/恢复）。
- 状态变化涉及多种操作（如增、删、改、重置），使用 `dispatch` 和 `action` 使逻辑更清晰。
- 深度嵌套的组件需要传递状态更新逻辑（配合 `useContext` 可模拟全局状态管理）。

## 使用方法

1. **定义 `reducer` 函数**  
   接收当前状态 `state` 和一个 `action` 对象（通常包含 `type` 和 `payload`），根据 `action.type` 返回新状态。

2. **调用 `useReducer`**  
   `const [state, dispatch] = useReducer(reducer, initialState);`  
   - `state`：当前状态值  
   - `dispatch`：触发更新的函数，调用时传入 `action` 对象

3. **在事件处理中 `dispatch` 动作**  
   `dispatch({ type: 'INCREMENT', payload: 1 })`

## 简单示例：购物车商品数量管理

下面实现一个管理商品数量的组件，支持增加、减少和重置。这比单纯的计数器更贴近实际业务，也体现了管理对象状态的优势。

```jsx
import React, { useReducer } from 'react';

// 1. 定义初始状态
const initialState = {
  count: 0,
  maxLimit: 10,
  minLimit: 0,
};

// 2. 定义 reducer 函数
function counterReducer(state, action) {
  switch (action.type) {
    case 'increment':
      // 不允许超过最大限制
      if (state.count >= state.maxLimit) return state;
      return { ...state, count: state.count + 1 };
    case 'decrement':
      // 不允许低于最小限制
      if (state.count <= state.minLimit) return state;
      return { ...state, count: state.count - 1 };
    case 'reset':
      return { ...initialState, count: 0 };
    case 'setMaxLimit':
      // 更新最大限制，同时确保当前 count 不超过新限制
      return {
        ...state,
        maxLimit: action.payload,
        count: Math.min(state.count, action.payload),
      };
    default:
      throw new Error(`Unknown action: ${action.type}`);
  }
}

function ProductCounter() {
  const [state, dispatch] = useReducer(counterReducer, initialState);
  const { count, maxLimit, minLimit } = state;

  return (
    <div style={{ padding: 20 }}>
      <h2>商品数量: {count}</h2>
      <p>限制范围: {minLimit} ~ {maxLimit}</p>
      
      <button onClick={() => dispatch({ type: 'decrement' })} disabled={count <= minLimit}>
        -
      </button>
      <span style={{ margin: '0 12px' }}>{count}</span>
      <button onClick={() => dispatch({ type: 'increment' })} disabled={count >= maxLimit}>
        +
      </button>
      
      <button onClick={() => dispatch({ type: 'reset' })} style={{ marginLeft: 20 }}>
        重置
      </button>
      
      <div style={{ marginTop: 20 }}>
        <label>修改最大限制: </label>
        <input
          type="number"
          value={maxLimit}
          onChange={(e) =>
            dispatch({ type: 'setMaxLimit', payload: Number(e.target.value) })
          }
        />
      </div>
    </div>
  );
}

export default ProductCounter;
```

### 代码说明

- **多动作类型**：`increment`、`decrement`、`reset`、`setMaxLimit`，每种动作逻辑清晰集中在 reducer 内。
- **状态依赖**：加减时依赖当前的 `count`、`maxLimit`、`minLimit`，用 `useReducer` 可以安全地基于旧状态计算新状态。
- **边界检查**：reducer 内部保证不超出范围，避免状态不一致。
- **易于扩展**：如需增加“加 5”功能，只需增加一个 `type` 分支，无需修改组件主体。

## 对比 `useState`

| 场景                       | 推荐方案      |
|---------------------------|--------------|
| 单个简单值（boolean, number, string） | `useState`   |
| 多个不相关的值             | 多个 `useState` |
| 多个相关值（对象）且更新依赖当前值 | `useReducer` |
| 状态更新逻辑复杂，有多个子操作 | `useReducer` |
| 需要深层组件传递修改能力     | `useReducer` + `useContext` |

## 注意事项

- `reducer` 必须是**纯函数**：不要直接修改 `state`，返回新对象。
- 如果 `action` 无法处理，通常返回原 `state`（或抛错）。
- `useReducer` 的 `dispatch` 引用是稳定的，不会导致不必要的重新渲染（类似 `useState` 的 setter）。

通过这个示例可以看到，当状态逻辑涉及多个子值、多种操作以及边界条件时，`useReducer` 能让代码更可预测、易维护。
