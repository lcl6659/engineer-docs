# Q11：`useMemo` 与 `useCallback` 详解

两者都用于缓存，避免不必要的计算或子组件重渲染。

- **`useMemo(() => computeValue, deps)`**：缓存一个**计算结果**。只有 deps 变化时才重新计算，否则返回缓存的旧值。适用于昂贵计算或需要稳定引用的对象/数组。
- **`useCallback(fn, deps)`**：缓存一个**函数引用**。仅当 deps 变化时返回新的函数，配合 `React.memo` 可以避免子组件因函数引用变化而不必要地重渲染。

**注意**：不要提前过度优化，只在出现性能瓶颈或作为其他 Hook 的稳定依赖时才使用。


`useMemo` 和 `useCallback` 是 React 提供的**性能优化** Hook，用于**缓存**计算结果或函数引用，避免因不必要的重复计算或函数重新创建导致的子组件额外渲染。两者核心原理相似，但使用场景和返回值不同。

## 1. useMemo：缓存计算结果

### 作用
在**依赖项未变化**时，直接返回上一次缓存的值，避免每次渲染都执行昂贵的计算。

### 语法
```jsx
const cachedValue = useMemo(calculateValue, dependencies);
```
- `calculateValue`：一个返回需要缓存值的纯函数。
- `dependencies`：数组，当其中任一值变化时，重新执行 `calculateValue`。

### 示例：过滤大列表
```jsx
import { useMemo, useState } from 'react';

function FilteredList({ items, filterText }) {
  // 仅在 items 或 filterText 变化时重新过滤，否则复用上次结果
  const filtered = useMemo(() => {
    console.log('执行过滤计算...');
    return items.filter(item => item.includes(filterText));
  }, [items, filterText]);

  return (
    <ul>
      {filtered.map(item => <li key={item}>{item}</li>)}
    </ul>
  );
}
```

## 2. useCallback：缓存函数定义

### 作用
在**依赖项未变化**时，返回同一个函数引用（地址不变），避免因函数重新创建导致依赖该函数的子组件（如 `React.memo` 包裹的组件）不必要的重新渲染。

### 语法
```jsx
const cachedFn = useCallback(fn, dependencies);
```
- `fn`：需要缓存的函数。
- `dependencies`：数组，变化时返回新函数。

### 示例：配合 React.memo 避免子组件重渲染
```jsx
import { useCallback, useState, memo } from 'react';

const Child = memo(function Child({ onClick }) {
  console.log('Child 渲染了');
  return <button onClick={onClick}>点我</button>;
});

function Parent() {
  const [count, setCount] = useState(0);

  // 父组件每次渲染，onClick 的引用不变（除非 count 变化）
  const handleClick = useCallback(() => {
    console.log('按钮被点击');
  }, []); // 依赖为空，永远不变

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>父组件计数: {count}</button>
      <Child onClick={handleClick} />
    </div>
  );
}
```
如果不使用 `useCallback`，每次 `Parent` 渲染都会生成新的 `handleClick` 函数，导致 `Child` 即使被 `memo` 包裹也会重新渲染。

## 3. 核心区别

|                | `useMemo`                     | `useCallback`                      |
|----------------|-------------------------------|------------------------------------|
| **缓存内容**   | 计算**结果**（任意类型值）      | **函数本身**                       |
| **返回值**     | 缓存的值                       | 缓存的函数                         |
| **常见用途**   | 避免昂贵计算，派生数据          | 保持回调函数引用稳定，配合 `memo`   |
| **等价写法**   | -                             | `useMemo(() => fn, deps)`           |

实际上 `useCallback(fn, deps)` 完全等价于 `useMemo(() => fn, deps)`，只是写法更语义化。

## 4. 使用场景对比

### useMemo 适合：
- 耗时的数据转换（数组过滤、排序、复杂数学运算）
- 对象/数组的派生状态，避免每次渲染都重新创建新对象（影响子组件 `useEffect` 依赖）
- 保持**引用稳定性**的非函数值（例如传递给子组件的对象）

### useCallback 适合：
- 传递给子组件且子组件被 `React.memo` 优化的回调函数
- 作为其他 Hook（如 `useEffect`、`useCallback`）依赖项的函数
- 在 `context` 中传递的稳定函数

## 5. 注意事项

### ✅ 正确使用姿势
1. **依赖数组必须完整**：列出所有函数内用到的外部变量，否则缓存值可能过期。
2. **只对真正有性能开销的地方使用**：每个 Hook 都有内存和比较开销，过度优化反而降低性能。
3. **纯计算**：`useMemo` 的函数不应有副作用，也不要在里面修改状态。

### ❌ 常见误区
- **用 useMemo 来“缓存” JSX**：直接写组件即可，React 内部已有优化。
- **所有函数都用 useCallback**：除非该函数被传递给 `memo` 的子组件或作为其他 Hook 依赖，否则没必要。
- **依赖数组为空时，认为该值永远不会变**：实际上如果依赖引用变化（如 props 对象每次新建），仍会重新执行。

### 例子：错误使用 useMemo
```jsx
// ❌ 没有必要，字符串拼接很快
const greeting = useMemo(() => `Hello, ${name}`, [name]);

// ✅ 直接用普通变量
const greeting = `Hello, ${name}`;
```

## 6. 综合示例：防止子组件无效重绘

```jsx
import { useState, useCallback, useMemo, memo } from 'react';

const ExpensiveChild = memo(({ data, onItemClick }) => {
  console.log('ExpensiveChild render');
  return (
    <ul>
      {data.map(item => (
        <li key={item.id} onClick={() => onItemClick(item.id)}>
          {item.text}
        </li>
      ))}
    </ul>
  );
});

function Parent() {
  const [filter, setFilter] = useState('');
  const [count, setCount] = useState(0);

  // 缓存派生数据：过滤后的列表
  const filteredData = useMemo(() => {
    console.log('计算过滤列表');
    return rawData.filter(item => item.text.includes(filter));
  }, [filter]);

  // 缓存回调，避免 ExpensiveChild 重绘
  const handleItemClick = useCallback((id) => {
    console.log('点击了', id);
  }, []);

  return (
    <div>
      <input value={filter} onChange={e => setFilter(e.target.value)} />
      <button onClick={() => setCount(c => c + 1)}>计数: {count}</button>
      <ExpensiveChild data={filteredData} onItemClick={handleItemClick} />
    </div>
  );
}
```
- 当 `count` 变化，`Parent` 重新渲染，但 `filteredData` 和 `handleItemClick` 引用不变 → `ExpensiveChild` 不会重新渲染。
- 当 `filter` 变化，`filteredData` 重新计算 → 子组件正常更新。

## 7. 总结

| Hook          | 返回什么 | 何时重新计算/创建 | 主要目的                     |
|---------------|----------|------------------|------------------------------|
| `useMemo`     | 值       | 依赖项变化        | 避免昂贵的计算，保持值的稳定引用 |
| `useCallback` | 函数     | 依赖项变化        | 保持函数引用稳定，避免子组件无效渲染 |

记住：性能优化是有代价的，优先保证代码正确性，只在必要时使用 `useMemo` 和 `useCallback`。如果不确定是否需要，可以先不用，等遇到性能瓶颈时再分析添加。



`React.memo` 和 `PureComponent` 都是 React 提供的**性能优化**手段，用于减少不必要的组件重新渲染。它们的核心思想相同：**通过浅比较（shallow compare）判断 props 或 state 是否变化，如果没有变化则跳过本次渲染（复用上次渲染结果）**。

下面分别讲解它们的用法、原理以及适用场景。

## 1. PureComponent（类组件）

`React.PureComponent` 是 `React.Component` 的子类，它**自动为类组件实现了 `shouldComponentUpdate`**，对 props 和 state 进行**浅比较**。

```jsx
import React, { PureComponent } from 'react';

class Child extends PureComponent {
  render() {
    console.log('Child render');
    return <div>{this.props.name}</div>;
  }
}

class Parent extends React.Component {
  state = { count: 0, user: { name: 'Alice' } };

  render() {
    return (
      <div>
        <button onClick={() => this.setState({ count: this.state.count + 1 })}>
          Count: {this.state.count}
        </button>
        {/* 只有当 user 对象的引用变化时，Child 才会重新渲染 */}
        <Child name={this.state.user.name} />
      </div>
    );
  }
}
```

### 重要特性
- 浅比较仅比较第一层属性（`props.name === prevProps.name`）。
- 如果 props 或 state 是复杂对象/数组，**内部数据变化但引用不变**，组件将**不会更新**（这是常见 bug 来源）。
- 适用于**props 和 state 较为简单**或使用**不可变数据**的场景。

### 手动控制更新
如果需要在 `PureComponent` 中自定义更新逻辑，可以写 `shouldComponentUpdate`，但注意不要同时使用两者。

## 2. React.memo（函数组件）

`React.memo` 是一个**高阶组件**，用于函数组件，效果类似 `PureComponent`，但**仅对 props 进行浅比较**（不比较 state）。

```jsx
import React, { memo, useState } from 'react';

const Child = memo(function Child({ name }) {
  console.log('Child render');
  return <div>{name}</div>;
});

function Parent() {
  const [count, setCount] = useState(0);
  const [user, setUser] = useState({ name: 'Alice' });

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>Count: {count}</button>
      <button onClick={() => setUser({ name: 'Bob' })}>Change name</button>
      <Child name={user.name} />
    </div>
  );
}
```

### 自定义比较函数
`memo` 接受第二个参数，一个比较函数 `(prevProps, nextProps) => boolean`：返回 `true` 时跳过渲染，`false` 时重新渲染。

```jsx
const Child = memo(
  ({ user }) => <div>{user.name}</div>,
  (prevProps, nextProps) => prevProps.user.name === nextProps.user.name
);
```

## 3. 浅比较的原理与注意事项

### 浅比较做了什么？
```js
function shallowEqual(objA, objB) {
  if (objA === objB) return true;
  if (typeof objA !== 'object' || objA === null ||
      typeof objB !== 'object' || objB === null) return false;
  const keysA = Object.keys(objA);
  const keysB = Object.keys(objB);
  if (keysA.length !== keysB.length) return false;
  for (let key of keysA) {
    if (!objB.hasOwnProperty(key) || objA[key] !== objB[key]) return false;
  }
  return true;
}
```
- 对于基本类型（string, number, boolean），比较值。
- 对于对象/数组，比较**引用**（是否指向同一内存地址）。

### 常见陷阱
```jsx
// ❌ 错误：改变了对象内部属性，但引用不变 → 组件不更新
const [user, setUser] = useState({ name: 'Alice' });
user.name = 'Bob';
setUser(user);  // 同一个对象引用，浅比较认为没变化

// ✅ 正确：创建新对象
setUser({ ...user, name: 'Bob' });
```

## 4. 对比总结

| 特性               | `React.PureComponent`         | `React.memo`                     |
|-------------------|-------------------------------|----------------------------------|
| **适用组件类型**   | 类组件                        | 函数组件                         |
| **比较范围**       | props **和** state            | 仅 props                         |
| **自定义比较**     | 手动实现 `shouldComponentUpdate` | 第二个参数传入比较函数         |
| **默认比较方式**   | 浅比较                         | 浅比较                           |
| **是否影响子组件** | 跳过整个组件 render 及子组件树 | 同上                             |

## 5. 什么时候使用？

### ✅ 推荐使用场景
- 组件**渲染成本高**（大量数据、复杂子组件树）。
- 组件 props 和 state **经常不变**或变化规律明确。
- 在列表/表格中渲染大量重复结构。
- 已经使用了**不可变数据**（Immutable.js、Immer 等）。

### ❌ 不推荐或无效场景
- 组件本身很简单（纯展示、少量 DOM），优化带来的比较开销可能大于渲染开销。
- **props 每次都会变化**（例如传入内联函数、新对象字面量）→ 浅比较永远为 false，优化失效。
- 没有明确的性能瓶颈时盲目添加 → 增加代码复杂性和潜在的 bug 风险。

## 6. 常见优化搭配：`useCallback` + `useMemo`

对于函数组件中的 `memo`，父组件传递的函数或对象需要配合 `useCallback` / `useMemo` 保持引用稳定，否则每次父组件渲染都会产生新函数/新对象，导致子组件（memo 包裹）重新渲染。

```jsx
const Parent = () => {
  const [count, setCount] = useState(0);
  
  // ✅ 保持函数引用稳定
  const handleClick = useCallback(() => {
    console.log('clicked');
  }, []);
  
  // ✅ 保持对象引用稳定
  const style = useMemo(() => ({ color: 'red' }), []);
  
  return <Child onClick={handleClick} style={style} />;
};

const Child = memo(({ onClick, style }) => {
  return <button onClick={onClick} style={style}>Child</button>;
});
```

## 7. 代码示例：展示优化效果

```jsx
import React, { useState, memo } from 'react';

// 未优化的子组件：父组件每次渲染都会重新渲染它
const NormalChild = ({ value }) => {
  console.log('NormalChild render');
  return <div>{value}</div>;
};

// 优化的子组件：仅当 value 变化时才渲染
const MemoizedChild = memo(({ value }) => {
  console.log('MemoizedChild render');
  return <div>{value}</div>;
});

function App() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState('Hello');

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>Count: {count}</button>
      <input value={text} onChange={e => setText(e.target.value)} />
      <NormalChild value={text} />        {/* 每次点击按钮都会重新渲染 */}
      <MemoizedChild value={text} />      {/* 只有输入 text 变化才重新渲染 */}
    </div>
  );
}
```

## 总结

- **`PureComponent`** 和 **`React.memo`** 都是通过浅比较跳过不必要的渲染。
- 使用前**先测量性能瓶颈**，不要过早优化。
- 必须搭配**不可变数据**，否则优化可能失效或导致 bug。
- 在函数组件中，`memo` + `useCallback`/`useMemo` 是最佳拍档。
- 如果 props 几乎每次都变（如动画、实时数据），优化反而有害，直接使用普通组件即可。
