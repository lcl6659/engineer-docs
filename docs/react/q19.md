# Q19：Portals（传送门）

`ReactDOM.createPortal(child, container)` 可以将子节点渲染到父组件 DOM 树以外的 DOM 节点，但事件冒泡依然沿 React 组件树传播。

**主要用途**：模态框、悬浮提示等不受父容器样式（overflow、z-index）影响的 UI。


React Portals（传送门）提供了一种将子节点渲染到父组件 DOM 树之外（但逻辑上仍是其子组件）的方式。它突破了 React 默认的嵌套渲染顺序，常用于处理**模态框、提示框、下拉菜单、悬浮层**等需要视觉上脱离当前容器层叠顺序的场景。

## 1. 核心 API

```jsx
ReactDOM.createPortal(child, container)
```

- **child**：任何可渲染的 React 元素（JSX、Fragment、字符串、数字等）。
- **container**：一个真实的 DOM 节点（通常通过 `document.getElementById` 等方式获取），子节点会被渲染到该 DOM 元素内。

## 2. 为什么需要 Portal？

默认情况下，React 会将组件按照嵌套结构渲染到父组件的 DOM 节点下。但某些 UI 元素（如模态框、Tooltip）需要：

- **视觉上跳出父容器的 `overflow: hidden`、`z-index` 层级限制**。
- **避免受父容器 CSS（背景色、滤镜等）影响**。
- **挂载到 `body` 或其他顶层元素，便于全局定位**。

Portal 允许我们将 JSX 逻辑保持在原组件层级（方便 props、状态传递、事件监听），但实际 DOM 渲染到任意指定位置。

## 3. 基本用法示例

```jsx
import ReactDOM from 'react-dom';

function Modal({ children, onClose }) {
  // 获取 body 下的 modal-root 元素（需要在 index.html 中预先定义）
  const modalRoot = document.getElementById('modal-root');
  if (!modalRoot) return null;

  // 使用 createPortal 把内容渲染到 modal-root 中
  return ReactDOM.createPortal(
    <div className="modal-overlay">
      <div className="modal-content">
        {children}
        <button onClick={onClose}>关闭</button>
      </div>
    </div>,
    modalRoot
  );
}

function App() {
  const [show, setShow] = useState(false);
  return (
    <div style={{ position: 'relative', zIndex: 1, overflow: 'hidden' }}>
      <button onClick={() => setShow(true)}>打开模态框</button>
      {show && <Modal onClose={() => setShow(false)}>这是一个传送门模态框</Modal>}
    </div>
  );
}
```

HTML 需要预留挂载点：
```html
<!-- public/index.html -->
<body>
  <div id="root"></div>
  <div id="modal-root"></div>
</body>
```

## 4. 事件冒泡机制（重要）

**Portal 在逻辑上仍是 React 组件树的一部分，因此事件会按 React 树冒泡，而不是按 DOM 树。**

```jsx
// 父组件
<div onClick={() => console.log('Parent click')}>
  <PortalChild />
</div>

// PortalChild 实际渲染到 body 下
function PortalChild() {
  return ReactDOM.createPortal(
    <button onClick={() => console.log('Button click')}>点我</button>,
    document.body
  );
}
```
点击按钮时控制台输出：
```
Button click
Parent click
```
虽然按钮 DOM 不在父 div 内，但事件冒泡依然能触达父组件的 `onClick`。这让我们可以方便地由父组件捕获 Portal 内的事件，非常灵活。

## 5. 常见应用场景

| 场景                 | 原因                                                         |
| -------------------- | ------------------------------------------------------------ |
| **模态框 / 对话框**  | 避免被父容器的 `z-index`、`overflow: hidden`、`transform` 等样式截断或影响 |
| **全局提示（Toast）** | 挂载到 `body`，便于定位在屏幕中央/角落，且不依赖当前组件布局 |
| **下拉菜单 / 选择器** | 突破父容器 `overflow: auto` 的滚动限制，可悬浮在任意位置       |
| **悬浮提示（Tooltip）** | 跟随鼠标但不会被父容器裁剪                                    |
| **拖拽元素**         | 拖拽时浮层应脱离原容器，挂载到全局                           |

## 6. 与普通渲染的对比

| 特性           | 普通子组件渲染                      | React Portal                           |
| -------------- | ----------------------------------- | -------------------------------------- |
| **DOM 位置**   | 父组件 DOM 内部嵌套                 | 自定义 DOM 容器（通常为 `body` 顶层）  |
| **CSS 层叠**   | 受父级 `z-index`、`overflow` 限制   | 脱离父级约束，独立层叠                 |
| **事件冒泡**   | 按 DOM 树冒泡                       | 按 React 组件树冒泡（逻辑上保持父子关系） |
| **上下文支持** | 完全支持（Context、props、state）   | 完全支持（因为是逻辑父组件的子组件）     |
| **使用场景**   | 常规界面布局                        | 需要“跳出容器”的浮动层组件               |

## 7. 注意事项 & 最佳实践

1. **挂载点必须存在**：建议在 `useEffect` 中动态创建挂载点或确保 DOM 已就绪。
2. **服务端渲染（SSR）兼容**：`document` 在服务端不存在，需判断 `typeof window !== 'undefined'` 或只在客户端执行 Portal。
3. **样式管理**：Portal 内的 CSS 需单独考虑，一般通过全局样式或 CSS Modules 作用于挂载点下的类名。
4. **可访问性**：模态框等组件需配合 `role="dialog"`、`aria-modal` 以及焦点管理（自动聚焦到关闭按钮或模态框内）。
5. **多个 Portal 同时存在**：可以挂载到不同容器或同一个容器，按渲染顺序堆叠（后者在上层）。
6. **Portal 的卸载**：当包含 Portal 的组件卸载时，Portal 内的 React 子节点也会被自动移除。

## 8. 进阶：动态创建 Portal 容器

```jsx
function usePortal(containerId = 'portal-root') {
  const [container, setContainer] = useState(null);

  useEffect(() => {
    let element = document.getElementById(containerId);
    if (!element) {
      element = document.createElement('div');
      element.id = containerId;
      document.body.appendChild(element);
    }
    setContainer(element);
    return () => {
      if (element.parentNode && element.childNodes.length === 0) {
        element.parentNode.removeChild(element);
      }
    };
  }, [containerId]);

  return container;
}

function Portal({ children }) {
  const container = usePortal();
  return container ? ReactDOM.createPortal(children, container) : null;
}
```

## 9. 总结

- **React Portals 提供了将子节点渲染到父组件 DOM 树之外的能力**，常用于需要突破容器视觉限制的 UI 组件。
- **事件冒泡仍然遵循 React 组件树**，便于逻辑上保持父子交互。
- 结合 `ReactDOM.createPortal` 使用时，注意挂载点的存在性、SSR 兼容以及可访问性要求。
- 现代 React 中，Portal 是构建高质量浮动层组件（模态框、提示框等）的标配方案。
