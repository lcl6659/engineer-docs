# Q20：错误边界（Error Boundary）

错误边界是一种 React 类组件，用于捕获**子组件树**中的 JavaScript 错误，防止整个应用崩溃，并展示降级 UI。

- 需实现 `static getDerivedStateFromError()` 和/或 `componentDidCatch()`。
- 无法捕获：事件处理器错误、异步代码、服务端渲染及自身的错误。

---

错误边界（Error Boundary）是 React 提供的一种**捕获子组件树中 JavaScript 错误**并显示备用 UI 的机制，可以防止整个应用因部分组件崩溃而白屏。它类似于 JavaScript 中的 `catch {}`，但只适用于**声明式渲染**、**生命周期方法**以及**构造函数**中的错误。

## 1. 如何创建错误边界

错误边界是一个**类组件**（目前 Hook 无法替代），需要实现以下两个生命周期方法之一或全部：

- `static getDerivedStateFromError(error)`：在渲染备用 UI 之前调用，用于更新 state 表明出错。
- `componentDidCatch(error, errorInfo)`：用于记录错误日志（例如发送到错误监控服务）。

```jsx
class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false };
  }

  static getDerivedStateFromError(error) {
    // 更新 state 使下一次渲染显示降级 UI
    return { hasError: true };
  }

  componentDidCatch(error, errorInfo) {
    // 可以在这里将错误日志上报给服务器
    console.error('Error caught:', error, errorInfo);
  }

  render() {
    if (this.state.hasError) {
      // 自定义降级 UI
      return <h2>出错了，请稍后重试。</h2>;
    }
    return this.props.children;
  }
}
```

## 2. 使用错误边界

用错误边界组件包裹可能出错的子组件：

```jsx
<ErrorBoundary>
  <MyWidget />
</ErrorBoundary>
```

可以多次使用，对不同区域分别隔离。错误边界只捕获**其子组件树**中的错误，不影响兄弟组件或自身。

## 3. 捕获范围与限制

### ✅ 能捕获的错误
- 构造函数、render 方法
- 所有生命周期方法（如 `componentDidMount`、`componentDidUpdate` 等）
- 子组件整棵树的上述方法中的错误

### ❌ 不能捕获的错误
- **事件处理器**中的错误（需用普通 `try/catch`）
- **异步代码**（`setTimeout`、`requestAnimationFrame` 回调）
- **服务端渲染**（SSR）中的错误
- **错误边界自身**（比如它的 render 方法或生命周期内抛出的错误）
- **非 React 代码**（如原生事件监听、普通 JS 函数）

> 对于事件处理错误，可以这样捕获：
> ```jsx
> const handleClick = () => {
>   try {
>     // 可能出错的代码
>   } catch (error) {
>     // 处理错误或上报
>   }
> };
> ```

## 4. 错误边界的意义与最佳实践

- **避免白屏**：一个组件崩溃不会导致整个应用卸载，用户仍能与其它正常区域交互。
- **渐进增强**：可在生产环境保留错误边界，开发环境错误仍会冒泡到控制台。
- **粒度控制**：通常在最外层（根组件）放一个全局错误边界，同时在关键模块（如侧边栏、评论区）放置独立边界。
- **上报错误**：在 `componentDidCatch` 中调用错误监控服务（如 Sentry、Bugsnag 等）。

## 5. 完整示例（含事件错误处理）

```jsx
class BuggyCounter extends React.Component {
  state = { count: 0 };

  handleClick = () => {
    try {
      if (this.state.count === 3) {
        throw new Error('Simulated event error');
      }
      this.setState(({ count }) => ({ count: count + 1 }));
    } catch (e) {
      console.log('Caught in event handler:', e.message);
      // 可以在这里更新 UI 或上报
    }
  };

  render() {
    if (this.state.count === 5) {
      // 这个错误会被错误边界捕获（发生在 render）
      throw new Error('Crashed in render');
    }
    return <button onClick={this.handleClick}>Count: {this.state.count}</button>;
  }
}

function App() {
  return (
    <ErrorBoundary>
      <BuggyCounter />
    </ErrorBoundary>
  );
}
```

## 6. 错误边界与 Hook 的现状

React 官方**暂无提供 Hook 形式的错误边界**，因为 `try/catch` 无法捕获声明式渲染期间的错误。但可以通过一个自定义 Hook 配合状态管理模拟特定场景（如事件错误、异步错误），不过无法替代完整的错误边界。

## 总结

| 特性             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **定义方式**     | 类组件，实现 `static getDerivedStateFromError` 和/或 `componentDidCatch` |
| **作用**         | 捕获子组件树中的渲染错误，显示备选 UI                         |
| **不能捕获**     | 事件处理、异步代码、SSR、错误边界自身的错误                   |
| **使用场景**     | 全局兜底、模块级隔离、核心功能保护                           |
| **配合工具**     | 错误日志上报（Sentry 等）                                    |

错误边界是生产级 React 应用必不可少的兜底方案，能显著提升用户体验。
