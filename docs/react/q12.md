# Q12：`useContext` 与 Context API 如何跨组件传值

Context 用于在组件树中共享全局数据，无需逐层 props 传递。

1. 创建：`const MyCtx = React.createContext(defaultValue)`
2. 提供：`<MyCtx.Provider value={data}>`
3. 消费：
   - 函数组件：`const data = useContext(MyCtx)`
   - 类组件：`static contextType = MyCtx` 或 `<MyCtx.Consumer>`

**注意**：Provider 的 value 变化时，所有使用该 Context 的组件都会重渲染。对于高频更新的数据，应拆分多个 Context，或用状态管理库进行细粒度订阅。



React 的 Context API 提供了一种在组件树中**跨层级传递数据**的方法，无需手动将 props 一层层传递（prop drilling）。`useContext` 是 React 提供的 Hook，用于在函数组件中方便地消费 Context。

## 核心三步骤

1. **创建 Context 对象**：`const MyContext = React.createContext(defaultValue);`
2. **提供值**：在组件树上层用 `MyContext.Provider` 包裹，并通过 `value` 属性传递数据。
3. **消费值**：在任意下层组件中调用 `useContext(MyContext)` 获取当前值。

## 简单示例：主题切换

```jsx
import React, { createContext, useContext, useState } from 'react';

// 1. 创建 Context
const ThemeContext = createContext('light');

// 顶层组件：提供主题
function App() {
  const [theme, setTheme] = useState('light');
  const toggleTheme = () => setTheme(theme === 'light' ? 'dark' : 'light');

  return (
    // 2. 通过 Provider 提供 value
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      <Toolbar />
    </ThemeContext.Provider>
  );
}

// 中间组件：无需传递任何 props
function Toolbar() {
  return (
    <div>
      <ThemedButton />
    </div>
  );
}

// 深层组件：通过 useContext 直接获取
function ThemedButton() {
  // 3. 消费 Context 值
  const { theme, toggleTheme } = useContext(ThemeContext);
  return (
    <button
      onClick={toggleTheme}
      style={{
        background: theme === 'light' ? '#fff' : '#333',
        color: theme === 'light' ? '#000' : '#fff'
      }}
    >
      当前主题：{theme}
    </button>
  );
}
```

## 进阶：跨组件传递复杂状态（模拟全局 store）

可以将 `useReducer` 与 Context 结合，实现轻量级的状态管理：

```jsx
const StoreContext = createContext();

function StoreProvider({ children }) {
  const [state, dispatch] = useReducer(reducer, initialState);
  return (
    <StoreContext.Provider value={{ state, dispatch }}>
      {children}
    </StoreContext.Provider>
  );
}

// 任意子组件
function Child() {
  const { state, dispatch } = useContext(StoreContext);
  // 使用 state 和 dispatch...
}
```

## 注意事项

| 要点 | 说明 |
|------|------|
| **默认值** | `createContext(defaultValue)` 仅在组件树中没有匹配的 Provider 时才会生效。 |
| **重渲染** | Provider 的 `value` 变化时，所有消费该 Context 的组件都会重新渲染（即使使用了 `React.memo`）。可以通过拆分 Context 或使用 `useMemo` 优化 `value` 对象。 |
| **多个 Context** | 可以嵌套使用多个 Provider，每个 `useContext` 只对应一个 Context 对象。 |
| **非组件内消费** | `useContext` 只能在函数组件或自定义 Hook 中调用。类组件可使用 `MyContext.Consumer`。 |

## 对比 props 传递

| 方式 | 优点 | 缺点 |
|------|------|------|
| **Props drilling** | 简单直接，数据流清晰 | 中间组件被迫接收无关 props，代码冗余 |
| **Context + useContext** | 跳过中间层，避免 prop drilling | 增加耦合，不利于复用；过度使用会影响性能 |

## 总结

- **`createContext`** 创建一个上下文容器。
- **`Provider`** 提供具体的值，必须包裹在需要共享数据的组件树外层。
- **`useContext`** 在任意深度的子组件中读取该值，并自动响应值的变化。

Context 最适合用于**全局或半全局**的状态共享，例如当前认证用户、主题、语言偏好、UI 布局状态等。对于频繁更新的数据，建议结合 `useReducer` 并优化，或使用专门的第三方状态管理库。
