# Q17：高阶组件（HOC）的概念与应用

**概念**：高阶组件是一个**函数**，接收一个组件，返回一个新的增强组件。

```javascript
const EnhancedComponent = higherOrderComponent(WrappedComponent);
```

**应用**：权限控制、埋点、数据获取、条件渲染，复用逻辑。

**注意**：
- 不要修改原始组件，使用组合。
- 透传不相关的 props。
- 通常以 `with` 开头命名，如 `withRouter`。
- 可配合 `hoist-non-react-statics` 解决静态方法丢失问题。



高阶组件（Higher-Order Component，HOC）是 React 中一种用于**复用组件逻辑**的高级技术。它本质上是一个**函数**，接收一个组件作为参数，并返回一个**增强后的新组件**。

```jsx
const EnhancedComponent = higherOrderComponent(WrappedComponent);
```

HOC 不是 React API 的一部分，而是基于 React 组合特性（组件作为一等公民）衍生出的一种设计模式。

## 1. HOC 的核心概念

### 为什么要用 HOC？
- **横向复用逻辑**：跨多个组件共享相同的逻辑（如权限校验、日志记录、数据获取、主题切换等）。
- **解耦**：将通用逻辑抽离，使业务组件保持纯净（只关心 UI 和自身状态）。
- **条件渲染**：根据某些条件决定是否渲染被包裹组件。

### 基本使用方式

```jsx
// 一个简单的日志 HOC
function withLogger(WrappedComponent) {
  return function(props) {
    useEffect(() => {
      console.log(`Component ${WrappedComponent.name} mounted`);
      return () => console.log(`Component ${WrappedComponent.name} unmounted`);
    }, []);
    // 透传所有 props
    return <WrappedComponent {...props} />;
  };
}

// 使用
const EnhancedButton = withLogger(MyButton);
```

## 2. 常见应用场景

| 场景               | 说明                                                         |
| ------------------ | ------------------------------------------------------------ |
| **权限控制**       | 检查用户角色，无权限则返回 null 或重定向组件。                |
| **数据获取**       | 封装 API 请求，管理 loading/error 状态，将数据作为 props 注入。 |
| **样式注入**       | 为组件自动添加 className、内联样式或 CSS-in-JS 规则。          |
| **状态提升/共享**  | 通过 HOC 提供共享状态（如表单值、键盘快捷键监听）。           |
| **性能监控**       | 记录组件渲染次数、耗时等。                                   |
| **逻辑剥离**       | 将与渲染无关的生命周期逻辑（如订阅、定时器）迁移到 HOC。      |

## 3. 实现一个实用的 HOC：数据获取

```jsx
function withDataFetching(url, mapDataToProps = data => ({ data })) {
  return function(WrappedComponent) {
    return function(props) {
      const [data, setData] = useState(null);
      const [loading, setLoading] = useState(true);
      const [error, setError] = useState(null);

      useEffect(() => {
        fetch(url)
          .then(res => res.json())
          .then(data => {
            setData(data);
            setLoading(false);
          })
          .catch(err => {
            setError(err);
            setLoading(false);
          });
      }, [url]);

      if (loading) return <div>Loading...</div>;
      if (error) return <div>Error: {error.message}</div>;

      const extraProps = mapDataToProps(data);
      return <WrappedComponent {...props} {...extraProps} />;
    };
  };
}

// 使用
const UserList = ({ users }) => (
  <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>
);

const EnhancedUserList = withDataFetching('/api/users', data => ({ users: data }))(UserList);
```

## 4. 需要注意的约定与陷阱

### 约定
- **透传无关 props**：HOC 应该将未使用的 props 原样传递给被包裹组件。
- **包装显示名称**：方便调试，建议设置 `displayName`。
  ```jsx
  function withHOC(Wrapped) {
    const Enhanced = props => <Wrapped {...props} />;
    Enhanced.displayName = `withHOC(${getDisplayName(Wrapped)})`;
    return Enhanced;
  }
  function getDisplayName(Comp) { return Comp.displayName || Comp.name || 'Component'; }
  ```
- **不要在 render 方法中使用 HOC**：会导致组件卸载/重新挂载，丢失状态。
  ```jsx
  // ❌ 错误
  render() {
    const Enhanced = withHOC(MyComponent);
    return <Enhanced />;
  }
  // ✅ 正确：在组件外部定义
  const Enhanced = withHOC(MyComponent);
  ```

### 陷阱
- **静态方法丢失**：需要手动拷贝或使用 `hoist-non-react-statics` 工具。
- **ref 无法穿透**：默认 `ref` 指向外层 HOC 组件，需使用 `React.forwardRef`。
- **多个 HOC 嵌套顺序**：`withAuth(withLogger(MyComponent))`，外层 HOC 后执行，注意内层先获取 props。

## 5. React 中常用的高阶组件

### 1. `React.memo`
虽然常被归类为性能优化工具，但其本质是一个 HOC：接收组件，返回一个仅在 props 变化时重新渲染的组件。

```jsx
const MemoizedComponent = React.memo(MyComponent, arePropsEqual?);
```

### 2. `connect` (React-Redux)
最经典的 HOC，将 Redux store 的 state 和 dispatch 映射为组件的 props。

```jsx
import { connect } from 'react-redux';
const Enhanced = connect(mapStateToProps, mapDispatchToProps)(MyComponent);
```

### 3. `withRouter` (React Router v5)
为类组件注入路由相关的 props（`history`、`location`、`match`）。注：v6 推荐使用 hooks。

```jsx
import { withRouter } from 'react-router-dom';
class MyComponent extends React.Component { ... }
export default withRouter(MyComponent);
```

### 4. `withFormik` (Formik)
将表单状态（值、验证、提交等）注入组件。

```jsx
import { withFormik } from 'formik';
const Enhanced = withFormik({ ...config })(MyForm);
```

### 5. `injectIntl` (React Intl / FormatJS)
注入国际化函数 `formatMessage` 等。

```jsx
import { injectIntl } from 'react-intl';
const Enhanced = injectIntl(MyComponent);
```

### 6. `withStyles` (Material-UI v4 / JSS)
注入 CSS-in-JS 样式类名。v5 改用 hooks。

```jsx
import { withStyles } from '@material-ui/core/styles';
const StyledComp = withStyles(styles)(MyComponent);
```

### 7. `withTheme` (Styled-Components / emotion)
注入当前主题对象。

### 8. `observer` (MobX)
将 React 组件变为响应式组件，自动追踪可观察数据的变更并重新渲染。

```jsx
import { observer } from 'mobx-react';
const Enhanced = observer(MyComponent);
```

## 6. HOC vs Render Props vs Hooks

| 方式         | 优点                           | 缺点                         | 适用场景                   |
| ------------ | ------------------------------ | ---------------------------- | -------------------------- |
| **HOC**      | 链式调用，复用纯逻辑           | 命名冲突、静态方法丢失、ref穿透困难 | 横切关注点（日志、权限、数据） |
| **Render Props** | 数据来源明确，无命名冲突     | 回调嵌套，可读性下降         | 动态渲染逻辑               |
| **Hooks**    | 简洁直观，无额外组件树         | 规则限制（不能条件调用），类组件无法使用 | 状态逻辑复用（替代多数 HOC） |

**现状**：React Hooks 出现后，很多原本用 HOC 解决的场景（如数据获取、订阅）已被 `useEffect`、自定义 Hook 替代，但 HOC 在**组合第三方库**（如 Redux）或需要**修改组件渲染输出**（如添加额外元素）时仍有不可替代的地位。

## 7. 总结

- **HOC 是一个函数，输入组件，输出新组件**。
- 用于跨组件复用逻辑，避免重复代码。
- 必须遵守约定：透传 props、包装 displayName、不在 render 中调用。
- 常见 HOC 有 `React.memo`、`connect`、`withRouter`、`withFormik`、`injectIntl` 等。
- 优先考虑 Hooks，但在类组件或某些库集成场景下 HOC 仍是合理选择。
