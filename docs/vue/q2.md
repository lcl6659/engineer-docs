# Q2：Vue 的响应式原理（Vue 2 与 Vue 3 的区别）

响应式的核心是当数据变化时，依赖该数据的视图会自动更新。

**Vue 2**：
- 使用 `Object.defineProperty` 劫持对象属性的 `getter` 和 `setter`。
- 初始化时递归遍历对象的所有属性，将每个属性转为响应式。
- 数组的变更通过重写 7 个变更方法（`push`、`pop`、`shift`、`unshift`、`splice`、`sort`、`reverse`）实现监听。
- 缺点：无法检测到对象属性的添加和删除（需使用 `Vue.set`/`Vue.delete`），数组通过索引修改或修改 `length` 也无法检测。

**Vue 3**：
- 使用 ES6 的 `Proxy` 对整个对象进行代理，可直接拦截属性的读取、设置、删除、存在检查等。
- 无需递归初始遍历，访问时才进行深层追踪（惰性响应式）。
- 支持新增/删除属性、数组索引和 `length` 修改的检测。
- 响应式 API：`reactive`（对象）、`ref`（任意类型）、`computed`、`watch` 等。

**依赖收集与触发更新**：  
数据属性的 `getter` 中收集当前正在渲染的组件作为依赖（“订阅者”），当 `setter` 触发时通知所有订阅者重新渲染。



---

Vue 的响应式系统是其核心特性之一，能够自动追踪依赖并在数据变化时更新视图。Vue 2 和 Vue 3 在实现上有本质区别，主要体现在**底层代理方式**、**依赖收集机制**以及对**数组/对象变更检测**的能力上。

## 1. Vue 2 响应式原理

Vue 2 使用 **`Object.defineProperty`** 来劫持对象属性的 getter/setter，并结合**发布-订阅模式**实现响应式。

### 核心流程
1. **数据劫持**：在 `data` 选项返回的对象上，递归遍历所有属性，用 `Object.defineProperty` 将它们转为 getter/setter。
2. **依赖收集**：每个属性对应一个 **Dep**（依赖容器），在 getter 中收集当前正在执行的 **Watcher**（渲染 watcher 或 computed watcher）。
3. **派发更新**：当属性值变化时，setter 会通知 Dep，Dep 遍历所有订阅的 Watcher 执行更新（重新渲染组件或重新计算）。

### 简化的实现示例
```js
function defineReactive(obj, key, val) {
  const dep = new Dep();
  Object.defineProperty(obj, key, {
    get() {
      if (Dep.target) dep.addSub(Dep.target);
      return val;
    },
    set(newVal) {
      if (newVal !== val) {
        val = newVal;
        dep.notify();
      }
    }
  });
}
```

### Vue 2 的局限性
- **无法检测对象属性的添加/删除**：因为 `defineProperty` 必须在初始化时定义所有属性。解决方案：`Vue.set` / `this.$set`。
- **对数组变更的检测不完善**：只能拦截 `push`、`pop`、`shift`、`unshift`、`splice`、`sort`、`reverse` 这 7 个变异方法，通过重写数组原型实现；而直接通过索引修改或修改 length 无法响应，需用 `$set` 或 `splice`。
- **性能开销**：需要在初始化时递归遍历所有属性，对于深层嵌套的大对象，性能较差。
- **无法处理 Map、Set、WeakMap 等原生数据结构**。

## 2. Vue 3 响应式原理

Vue 3 使用 **ES6 Proxy** 和 **Reflect** 实现响应式，提供了更强大、更高效的代理能力。

### 核心改动
- **Proxy 代理整个对象**：不需要递归遍历，直接在访问时动态拦截。
- **依赖收集基于 `track` / `trigger`**：每个属性对应一个依赖管理中心（`targetMap` -> `depsMap` -> `dep`）。
- **使用 `Reflect` 保证 this 正确性**：在 proxy handler 中使用 `Reflect.get/set`，并传入 receiver。
- **支持响应式 Map、Set、WeakMap、WeakSet**。

### 简化的实现示例
```js
function reactive(target) {
  const handler = {
    get(target, key, receiver) {
      track(target, key); // 依赖收集
      return Reflect.get(target, key, receiver);
    },
    set(target, key, value, receiver) {
      const oldVal = target[key];
      const result = Reflect.set(target, key, value, receiver);
      if (oldVal !== value) {
        trigger(target, key); // 派发更新
      }
      return result;
    }
  };
  return new Proxy(target, handler);
}
```

### Vue 3 的优势
- **可以检测属性的添加和删除**：Proxy 拦截 `set` 和 `deleteProperty` 操作，自然支持动态增删。
- **数组变更完全支持**：通过索引修改、`length` 修改都能被 Proxy 捕获。
- **懒代理**：只在访问嵌套对象时才将其转为响应式（按需递归），性能更好。
- **支持更多数据结构**：Map、Set、WeakMap、WeakSet 都可以被代理。
- **更好的错误处理和调试**：Proxy 提供更详细的元编程能力。

## 3. Vue 2 vs Vue 3 响应式核心区别

| 特性 | Vue 2 | Vue 3 |
|------|-------|-------|
| **底层 API** | `Object.defineProperty` | `Proxy` |
| **目标对象** | 必须预先知道所有属性 | 动态属性、删除、新增全支持 |
| **数组监听** | 只能拦截 7 个变异方法，索引/length 不响应 | 完全支持，通过索引修改也可触发 |
| **初始化性能** | 递归遍历所有属性，深度冻结 | 懒代理，按需嵌套递归 |
| **嵌套对象** | 递归深度代理，一次性完成 | 访问时再递归代理，更高效 |
| **Map/Set 支持** | 不支持 | 支持（`reactive` 对 Map/Set 做响应式） |
| **开发体验** | 需要使用 `$set` 或 `Vue.set` | 直接赋值即可，更符合直觉 |

## 4. 其他重要差异：`ref` 与 `reactive`

- **Vue 2**：所有数据都定义在 `data` 函数返回的对象中，内部自动递归响应化。
- **Vue 3**：引入 Composition API，提供 `ref` 和 `reactive`。
  - `reactive`：用于对象/数组/Map/Set，基于 Proxy 实现。
  - `ref`：用于基本类型（或对象），通过 `.value` 访问，内部对象用 `reactive` 处理。
  - 对于基本类型，`ref` 创建一个带有 `value` 属性的响应式对象，同样通过 Proxy 或 `Object.defineProperty`（某些边缘情况）实现，但核心依赖系统同一。

## 5. 依赖收集系统的演变

- **Vue 2**：每个属性一个 Dep，Dep 包含多个 Watcher；Watcher 分为渲染 watcher、计算属性 watcher、用户 watcher。依赖收集通过全局 `Dep.target` 栈实现。
- **Vue 3**：使用 `effect` 函数（副作用）代替 Watcher，依赖关系通过 `track` 函数记录到 `targetMap` 中。`targetMap` 是 `WeakMap<target, Map<key, Set<effect>>>`。这种方式更灵活、更易于组合。

## 总结

Vue 3 的响应式系统相比 Vue 2 是一次彻底的重构，利用 Proxy 的优势解决了 Vue 2 中常见的限制（属性新增、数组索引、性能瓶颈等），同时提供了更现代的 Composition API 和更好的 TypeScript 支持。理解这两个版本的差异，对于迁移旧项目或设计响应式系统架构非常有帮助。
