# Q1：从输入 URL 到页面展示发生了什么？

这是一个经典的综合性问题，体现了你对网络、浏览器原理的整体理解。

1.  **URL 解析**  
    浏览器判断输入的是搜索内容还是请求的 URL。如果是 URL，会补全协议（默认 http/https），解析出协议、域名、端口、路径、参数等。

2.  **DNS 解析**  
    域名需要被解析为 IP 地址。浏览器会依次查询：浏览器缓存 → 操作系统 hosts 文件 → 路由器缓存 → ISP 的 DNS 缓存。如果都未命中，则进行递归查询或迭代查询，最终从根域名服务器、顶级域名服务器到权威域名服务器，拿到对应的 IP 地址。

3.  **建立 TCP 连接**  
    浏览器与服务器进行三次握手以建立可靠连接：
    - 客户端发送 `SYN` 包，进入 `SYN_SENT` 状态。
    - 服务器回复 `SYN+ACK` 包，进入 `SYN_RCVD` 状态。
    - 客户端发送 `ACK` 包，双方进入 `ESTABLISHED` 状态。
    如果是 HTTPS，还需进行 TLS 握手（协商协议版本、加密套件、交换证书、生成会话密钥），过程通常额外需要 2 个 RTT（往返时延）。

4.  **发送 HTTP 请求**  
    浏览器构建 HTTP 请求报文（包含请求行、请求头、请求体），发送给服务器。

5.  **服务器处理并响应**  
    服务器收到请求后，由后端程序进行处理，可能会查询数据库或调用其他服务，最终返回包含状态码和响应头的 HTTP 响应报文。

6.  **浏览器接收并解析渲染**  
    这是最关键的一步，进入了浏览器的渲染流程：
    - **解析 HTML，构建 DOM 树**：浏览器将字节流解析为字符，再通过词法、语法分析生成 DOM 节点，最终形成树结构。
    - **解析 CSS，构建 CSSOM 树**：解析 CSS 样式表，生成样式规则树。CSS 解析会阻塞渲染，因为页面需要知道最终的样式。
    - **合并生成 Render 树**：将 DOM 树与 CSSOM 树结合，生成渲染树。这个过程会排除不可见的节点（如 `display: none`）。
    - **布局（回流/Reflow）**：计算渲染树中每个节点的几何信息（在视口中的确切位置和大小）。
    - **绘制（重绘/Paint）**：将各节点绘制成屏幕上的实际像素。
    - **合成（Composite）**：如果页面中有分层，会把不同图层分开栅格化，最终由合成线程合并成页面，这个过程通常 GPU 参与，效率很高。

7.  **连接结束**  
    数据传输完毕后，通过四次挥手断开 TCP 连接（若为 HTTP/1.1 `Connection: keep-alive` 则保持连接可复用）。
