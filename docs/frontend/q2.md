# Q2：浏览器渲染原理（关键渲染路径）详解

回答时需讲透 DOM 树、CSSOM 树、渲染树、布局、绘制、合成，以及相关的重排、重绘、合成概念。

- **DOM 树**  
  HTML 解析器通过词法分析和语法分析，将字节 → 字符 → Token → 节点 → DOM 树。解析过程是渐进的，遇到 CSS 和 JS 会阻塞。

- **CSSOM 树**  
  CSS 是**阻塞渲染的资源**。浏览器必须下载并解析完所有 CSS，才能构建 CSSOM。CSS 解析可以和 DOM 构建并行，但不能立即显示。CSSOM 树记录了所有样式的规则。

- **渲染树**  
  由 DOM 和 CSSOM 合并而成，每个节点都包含视觉属性。`display: none` 的节点不会出现在渲染树中，但 `visibility: hidden` 会占据空间。

- **布局（Layout/Reflow）**  
  从根节点开始，遍历渲染树，计算每个节点在屏幕上的确切坐标和尺寸。**布局是一个递归且可能全局影响的过程**，例如窗口尺寸变化或元素几何属性改变都可能触发全局或局部布局。

- **绘制（Paint）**  
  根据渲染树和布局信息，将元素绘制成像素，填充颜色、边框、阴影等。绘制会生成一些绘制指令。

- **合成（Composite）**  
  现代浏览器会将页面分成多个图层，每个图层独立绘制并上传到 GPU，最终由合成线程合并为一张图显示在屏幕上。  
  **重排成本最高，重绘次之，仅合成本最低。**

- **常见属性对渲染的影响**  
  - **引起重排（导致重新布局）**：`width/height`、`padding`、`margin`、`left/top`、`font-size`、`display: none`、修改 DOM 结构等。
  - **引起重绘（不重新布局，只重画）**：`color`、`background-color`、`box-shadow` 等外观改变。
  - **只触发合成（不重排不重绘，性能最优）**：`transform` 和 `opacity`（当它们创建了独立合成层时）。


### 一、引起重排 (Reflow) 的操作

重排是最“昂贵”的操作，因为它需要浏览器重新计算元素在页面中的几何位置和尺寸。任何改变元素布局信息的操作都会触发重排。

**常见的 CSS 属性：**
- **盒模型相关**：`width`, `height`, `padding`, `margin`, `border`
- **定位和布局**：`display` (特别是 `none` 和 `block` 之间的切换), `position`, `top`, `left`, `right`, `bottom`, `float`, `clear`
- **文本和字体**：`font-size`, `font-family`, `line-height`, `text-align`
- **其他**：`overflow`, `flex` 相关属性, `grid` 相关属性, `vertical-align`

**易忽略的重排触发场景：**
- **改变窗口大小**（如 `resize` 事件）
- **读取某些布局属性**（强制同步重排）：如 `offsetTop`, `offsetLeft`, `offsetWidth`, `offsetHeight`, `scrollTop`, `scrollLeft`, `scrollWidth`, `scrollHeight`, `clientTop`, `clientLeft`, `clientWidth`, `clientHeight`, `getComputedStyle()`
- **添加或删除 DOM 元素**
- **改变 `className` 或内联样式**


#### 典型反模式（会导致性能问题）

```javascript
// 糟糕的循环：读-写-读-写...
for (let i = 0; i < elements.length; i++) {
  // 读取（可能触发重排）
  const height = elements[i].offsetHeight;
  // 写入样式（使布局变脏）
  elements[i].style.height = height + 10 + 'px';
}
```
每轮循环都发生一次强制重排 → 性能极差（O(n²) 复杂度）。

#### 正确做法（批量读写）

```javascript
// 1. 先读取所有依赖值（此时布局干净，不触发重排或只触发一次）
const heights = [];
for (let i = 0; i < elements.length; i++) {
  heights.push(elements[i].offsetHeight);
}
// 2. 再批量写入样式（所有样式变更被浏览器合并，最后统一触发一次重排）
for (let i = 0; i < elements.length; i++) {
  elements[i].style.height = heights[i] + 10 + 'px';
}
```
> 所以性能优化的黄金法则：避免在样式修改后紧接着读取布局属性，尽量将读操作和写操作分批进行。如果必须既读又写，先批量读，再批量写。

### 二、引起重绘 (Repaint) 但可能不引起重排的操作

重绘的代价比重排小。它只改变元素的外观样式，而不影响其几何尺寸和布局。

**常见的 CSS 属性（只改视觉，不改布局）：**
- **颜色相关**：`color`, `background-color`
- **边框样式**：`border-style`, `border-radius`, `border-color`（注意，`border-width` 会改变盒模型，引起重排）
- **背景和阴影**：`background-image`, `background-position`, `box-shadow`, `text-shadow`
- **轮廓**：`outline` 相关属性
- **可见性**：`visibility` (因为 `visibility: hidden` 仍占据空间，不影响布局)
- **其他**：`text-decoration`, `cursor`，`z-index`

### 三、只触发合成 (Composite) 的操作 (性能最佳)

这是性能最优的路径。浏览器会将元素提升到独立的图层（GPU 层），对这些图层的样式变换只需要 GPU 进行合成处理，完全跳过布局和绘制阶段。

**关键的 CSS 属性：**
- **`transform`**（推荐用于动画）：
  - `translate` (位移，代替 `top`/`left`)
  - `scale` (缩放)
  - `rotate` (旋转)
  - `skew` (倾斜)
- **`opacity`** (透明度)

**为什么它们性能好？**
- 这些操作不会影响其他元素的布局和绘制，只需要将已有的图层在 GPU 中进行移动、缩放或混合。

**如何确保触发合成而不是重绘/重排？**
- **使用 `will-change` 提示**：提前告知浏览器该元素即将发生变换。
  ```css
  .my-element {
    will-change: transform, opacity;
  }
  ```
- **确保元素处于独立的合成层**：
  - 动画元素最好有固定的 `transform: translateZ(0)` 或 `opacity` 配合 `will-change`。
  - 避免让动画元素影响其他元素（如使其 `position: fixed/absolute` 或避免使用 `margin` 动画）。

### 总结表格

| 操作类型 | 触发的大致成本 | 常见 CSS 属性 (举例) | 性能建议 |
| :--- | :--- | :--- | :--- |
| **重排 (Reflow)** | 很高 (整个布局树重新计算) | `width`, `height`, `margin`, `top`, `font-size`, `display`, `position` | **尽量避免**，或批量修改、脱离文档流（如 `position: fixed`） |
| **重绘 (Repaint)** | 中等 (只重画像素，不改位置) | `color`, `background-color`, `border-radius`, `visibility`, `box-shadow` | 不可避免时也可接受，但避免高频触发 |
| **只触发合成 (Composite)** | 很低 (GPU加速) | `transform`, `opacity` | **动画首选**，性能最佳 |

### 最佳实践建议
1.  **动画优先使用 `transform` 和 `opacity`**，而不是 `top`/`left`/`width`。
2.  使用 `will-change` 提前为动画元素创建独立图层，但不要滥用（图层太多会消耗内存）。
3.  避免在循环或高频事件（如 `scroll`, `resize`）中读取布局属性（`offsetTop` 等）。
4.  批量修改 CSS 样式，例如使用 `class` 替换，而不是逐个修改内联样式。
5.  对于复杂动画，考虑使用 `position: absolute`/`fixed` 使其脱离文档流，避免影响其他元素布局。
