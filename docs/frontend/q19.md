# Q19：HTTP 缓存策略（强缓存与协商缓存）

缓存是前端性能优化的核心。按流程判断：

1.  **首先检查强缓存（不发请求）**
    - **`Cache-Control`**（HTTP/1.1，优先级更高）：如 `max-age=3600` 代表 3600 秒内有效，`public` 可被任何缓存，`private` 仅浏览器，`no-cache` 需协商，`no-store` 不缓存。
    - **`Expires`**（HTTP/1.0）：绝对过期时间，有缺点（服务器时间偏差）。

    若命中强缓存，返回状态码 `200 (from memory/disk cache)`。

2.  **强缓存失效，走协商缓存（发请求询问）**
    - **`Last-Modified` / `If-Modified-Since`**：服务器返回文件最后修改时间，客户端下次请求时带上此字段。服务器比较，若未变则返回 `304`，不变则返回新资源。
    - **`ETag` / `If-None-Match`**：更精准的内容唯一标识，优先级高于 `Last-Modified`。解决了文件内容无变化但时间变了的问题。
    - 命中则返回 `304 Not Modified`，浏览器继续从缓存加载。

**缓存位置**：内存缓存（from memory cache，快速，关闭即清）、硬盘缓存（from disk cache，持久）、Service Worker 等。
