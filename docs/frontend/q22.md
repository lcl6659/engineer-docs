# Q22：XSS 与 CSRF 攻击的原理和防御

- **XSS（跨站脚本攻击）**
  - **原理**：攻击者将恶意脚本注入到网页中，当用户浏览时脚本执行，窃取信息或冒充用户。
  - **类型**：存储型（存到数据库）、反射型（URL 参数）、DOM 型（前端脚本漏洞）。
  - **防御**：
    - 对所有用户输入进行**转义/过滤**。
    - 使用 `CSP`（内容安全策略）限制脚本来源。
    - Cookie 设置 `HttpOnly`，防止 JS 读取。
    - 使用安全的 DOM 操作 API（如 `textContent` 替代 `innerHTML`）。

- **CSRF（跨站请求伪造）**
  - **原理**：用户登录某信任站点 A 后，在没有登出的情况下访问了恶意网站 B，B 诱导用户向站点 A 发起非预期的请求（如转账），由于携带了有效 Cookie，请求被认为合法。
  - **防御**：
    - **Token 校验**：前端请求携带服务端生成的随机 Token，且不存入 Cookie。
    - **SameSite Cookie**：设置 `SameSite: Strict` 或 `Lax`，跨站请求不携带。
    - **验证 Referer/Origin 头**：判断请求来源是否合法。
    - **双重 Cookie 验证**：请求中将某个值写入 Header 并与 Cookie 对比。
