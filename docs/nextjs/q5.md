# Q5：详细解释 ISR（增量静态再生成）及其工作原理

**原理**：SSG 页面在构建时生成，但 ISR 允许在运行时更新这些页面而无需重新构建整个站点。

**工作流程**：
1. 页面构建时生成静态 HTML。
2. 用户访问时返回该静态页面（CDN 缓存）。
3. 如果设置了 `revalidate` 时间（如 60 秒），并且该页面在缓存过期后第一次被请求，Next.js 仍会返回旧的（stale）缓存页面，同时在后台触发重新生成该页面。
4. 新生成的页面会替换旧缓存，后续请求得到新页面。

**配置示例（App Router）**：
```javascript
// app/blog/[slug]/page.js
export async function generateStaticParams() {
  return [{ slug: 'hello' }, { slug: 'world' }];
}

// 页面组件中：
export default async function Page({ params }) {
  const post = await fetch(`https://.../posts/${params.slug}`, {
    next: { revalidate: 60 } // 60秒后触发 ISR
  });
  // ...
}
```
也可以通过路由段配置 `export const revalidate = 60;`。

**优势**：拥有静态的速度，同时页面内容可以定期刷新，不需要完全重新部署。
